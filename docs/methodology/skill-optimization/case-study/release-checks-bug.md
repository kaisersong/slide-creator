# 发布包与窄屏检查 bug

记录日期：2026-10-08。方法论版本：1.0.1。此记录是项目内案例，不代表外部Issue。

## 发现与影响

为v2.31.0准备精简包时，使用上一版已发布ZIP补齐被Git忽略的企业主题，并在仅安装运行依赖的独立Python环境中生成。8个公开任务正常，但Kingdee主题被strict拒绝，原因是默认可见的notes-panel。去掉旧版本不支持的speaker_note后，同一输入在上一版v2.30.2包也复现；这是原有缺陷，不是新版本独有回退。

首轮完整发布门禁扩展检查66个能力矩阵场景，包含手机390×844、桌面/播放、最小输入、12种页面角色和图片输入。54通过、12失败，覆盖Bold Signal、Enterprise Dark、Neo-Brutalism、Neo-Retro Dev Deck与Notebook Tabs；多数是手机上窄列或大字号导致溢出，另有Neo-Retro桌面长列表裁切。原8类模型任务不能作为此能力矩阵全覆盖的证明。

## 根因与处理

旧custom renderer假设starter已经定义所有共享编辑样式。生成器仍插入notes-panel及编辑控制器，但部分starter没有该面板CSS；补上默认隐藏、active打开，以及缺失时的固定面板布局。保留原主题样式和上版企业资产，未为通过检查删除编辑能力。

一项回归的名称与docstring声称strict，其实际调用是strict=False，因而未捕获默认可见chrome；改成真实strict。手机排版对窄列进行重排，Enterprise旧格式的重复说明合并成一段，并保留全部行；split左侧仅移除已经在右侧卡片完整出现的同文标签。

共享导航也是执行层责任。Kingdee包只插入编辑控件而未提供导航/进度DOM；真实F5与方向键可用，但检查器无法按索引点击导航，退回不存在的Home重置时产生切页误判。补齐缺失节点、已有主题只保留一份节点；检查器另外兼容旧nav-dot选择器。这次切页故障的主因是缺失DOM，不能只归因于选择器。整页图片上的副标题还出现低对比；单纯改变文字颜色不足，需要使用主题主文字色配合不透明背景，并以实际浏览器量测确认。

## 验证与证据边界

原失败日志、首轮66场景失败报告及后续目标/完整门禁记录均保留。12个失败场景在修复后全通过；新增源码事实保留回归，原custom主题e2e改用strict。解压包已在只安装运行依赖的Python环境完成8类公开生成与Kingdee生成；9份文稿的双视口/两模式几何、真实Edit/Done备注隐藏/打开/关闭、F5和方向键全部通过。Cloudhub旧参考没有可执行布局，旧版与新版均被strict阻断；保留资产但不宣称生成可用。最终发行包完整门禁及GitHub下载字节比对另见release验证记录。

此记录不替代最终release验证报告，也不将程序重渲染当作新模型E2E。模型质量/耗时/token仍引用原冻结实现；标题语义的人工来源问题未由这些UI修复解决。最终发布证据记录在仓库的release报告中。

## 方法影响

新增案例补充v1.0已有原则，不改变通过或计量口径。今后检查测试实际断言，覆盖可分发能力而非只覆盖常用模型任务，并以真实发行包验证缺失资源和依赖。局部故障修复通过后，仍重跑约定完整发布门禁。
