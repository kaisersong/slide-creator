# Skill bug 记录模板

此模板用于项目内记录；复制模板不表示已经创建外部 Issue 或发送通知。

## 标识与状态

- bug ID、发现日期、Skill / 实现版本：待填。
- 方法论、语料、评分器和政策版本：待填。
- 状态：待复现 / 已复现 / 修复中 / 已局部验证 / 已完整验证 / 关闭。
- 严重性、影响范围和是否阻断采用：待填。
- 问题所在层：请求解析 / 契约 / 中间表示 / 程序 / 检查器 / 评审 / 交付，允许多层。

## 可复现证据

| 项目 | 记录 |
|---|---|
| 用户原始要求与来源定位 | 待填，区别要求和被分析材料 |
| 最小输入与完整原始输入 | 待填，保留丢失信息所需上下文 |
| 预期行为及其契约依据 | 待填 |
| 实际行为与具体错误位置 | 待填，标题/正文/备注等分别注明 |
| 运行入口、模型、环境和 runtime SHA | 待填 |
| trace、usage、产物与截图 | 待填 |
| 是否基线已有失败 | 待填，附原版本复现 |
| 自动检查/模型评分是否漏检 | 待填，不能只引用平均分 |
| 已完成副作用与已有输出 | 待填，重试前核对 |

## 根因与修复

解释因果链，不只复述现象：来源是否正确、模型是否写错、中间表示是否不足、程序是否删改、检查器是否漏测、用户是否看到错误交付。

- 单次修改：待填。
- 保留的兼容行为和受影响范围：待填。
- 修复是否触及模型契约或执行路径：待填。
- 回归输入如何加入下一版语料：待填。
- 原收据、原快照和旧结论如何保留：待填。

| 检查 | 实际结果 | 证据 | 能证明什么 |
|---|---|---|---|
| 原失败最小输入 | 待填 | 待填 | 待填 |

| 边界与旧输入兼容 | 待填 | 待填 | 待填 |

局部测试通过只能标为局部验证。只有约定的所有适用检查完成，且没有新阻断问题，才关闭该 bug。关闭单个 bug 不自动表示整个 Skill 可发布。

## 方法论影响

- 现有方法为何没提前发现：待填。
- 是案例缺失、检查覆盖不足，还是方法步骤/通过定义有问题：待填。
- 是否需要更新方法文档、模板、检查器或验收政策：待填。
- 受影响历史结论与需补跑的任务：待填。
- 方法论更新版本：1.0.1 / 1.1 / 2.0，按变化决定；记录修复证据后再发布。
- CHANGELOG 条目与证据链接：待填。
